# 发布步骤

这份指南写给你（作者）。标注 **【你来做】** 的步骤必须由你本人操作；标注 **【Claude 来做】** 的步骤由 Claude 完成，但会先征得你同意。

目标：把源码放到 GitHub，把插件发布到 VS Code 应用市场。

1. **【你来做】在 GitHub 网页上创建公开仓库。**
   本机没有安装 `gh`，所以请在浏览器里操作：登录 GitHub，点击右上角 “+”，选择 “New repository”，填写仓库名（例如 `web-nav`），可见性选 Public，不要勾选 “Add a README”，然后创建。

2. **【你来做】把仓库地址告诉 Claude。**
   例如 `https://github.com/你的用户名/web-nav`。

3. **【Claude 来做】填写 `package.json` 并推送。**
   Claude 会在 `package.json` 里填写 `repository`、`bugs`、`homepage`，再执行 `git remote add origin ...`。
   在你明确同意之前，Claude 不会执行 `git push`。

4. **【你来做】创建应用市场 publisher。**
   打开 https://marketplace.visualstudio.com/manage ，用微软账号登录，点击 “Create publisher”，填写 ID 和名称。请记住这个 ID，后面要用。

5. **【你来做】在 Azure DevOps 创建 PAT（个人访问令牌）。**
   - 打开 https://dev.azure.com ，登录同一个微软账号。
   - 点击右上角用户设置里的 “Personal access tokens”，选择 “New Token”。
   - Organization 选择 “All accessible organizations”。
   - Scopes 选择 “Custom defined”，找到 “Marketplace”，勾选 “Manage”。
   - 创建后立刻复制令牌，页面关闭后就看不到了。令牌等同于密码，不要发给别人，也不要提交到 git。

6. **把 publisher 填进 `package.json`。**
   把第 4 步的 ID 告诉 Claude，Claude 会在 `package.json` 中加上 `"publisher": "你的ID"`（你也可以自己改）。

7. **【你来做】登录 vsce。**
   ```
   npx @vscode/vsce login <你的publisher ID>
   ```
   按提示粘贴第 5 步的令牌。

8. **打包检查。**
   ```
   npx @vscode/vsce package
   ```
   此时应该没有任何警告。如果有警告，把输出发给 Claude 处理。

9. **【你来做】发布。**
   ```
   npx @vscode/vsce publish
   ```
   发布成功后，通常几分钟内可以在应用市场搜索到。以后更新时，修改 `package.json` 里的 `version`，并在 `CHANGELOG.md` 补充说明，再重复第 8、9 步。
