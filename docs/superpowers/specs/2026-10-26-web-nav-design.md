# 设计文档：网站导航 VS Code 插件（新项目）

日期：2026-10-26
状态：用户已确认（2026-10-26）

## 1. 背景和目的

用户想在 VS Code 里直接打开学习类网站（起因是菜鸟教程 runoob.com），不用切到浏览器。参考项目 `D:\prjx\urlNavigation`（别人写的“常用网站RSS”插件）能做到这一点，但网站列表是写死在代码里的，代码质量也一般。

用户想做一个**属于自己的插件**，主要有三个目的：

1. **自己日常用**：在 VS Code 侧边栏里管理和打开自己常用的网站。
2. **学习写 VS Code 插件**：由 Claude 写代码，写完后对照代码讲解给用户。用户此前已经读过 Claude 对参考项目的分析（贡献点、命令、TreeView、Webview、Disposable 等概念，以及参考项目的问题清单）。
3. **体验发布流程**：完整走一遍发布到 VS Code 插件市场的流程，让别人也能安装使用。

## 2. 目标

- 用户可以**自己添加网站**（这是用户最初的想法，也是核心功能），并在编辑器标签页里打开。
- 插件**内置一批推荐网站**，并且保证这些网站都能在 VS Code 里正常嵌入打开（用户的要求）。
- 用户添加的网站如果**不允许被 iframe 嵌入**，打开时显示一个**说明页**，不显示空白页（用户的要求）。
- 使用**最新的官方脚手架**重新搭建，修掉参考项目里的问题。
- 代码要清晰，能当学习材料：结构简单直白，注释适量，说明“为什么这样写”。
- 能用 `vsce` 打包，并发布到插件市场。

## 3. 非目标（这一版不做）

- 不做绕过“禁止嵌入”的代理。参考项目的 `proxy.ts` 方案有安全隐患（监听所有网卡），实际也跑不稳定。
- 不解决嵌入网站的登录问题（第三方 Cookie 等）。
- 不做 RSS 订阅、网页内容抓取、阅读进度这类功能。
- 不在侧边栏里做拖拽排序、多级文件夹（用户想调整顺序可以直接改 `settings.json`）。
- 不做多语言（界面只用中文）。

## 4. 反目标（技术上能跑通，但这样做就算失败）

- 说明页、侧边栏和编辑器风格不一致，颜色刺眼（用户明确提过：**不要“炸眼”**）。
- 插件在 VS Code 启动时就激活（`activationEvents: ["*"]`），拖慢编辑器启动。
- 推荐列表里有打不开的网站：推荐的网站必须都是实际验证过能嵌入的。
- 代码绕来绕去、不好讲解，失去了学习材料的作用。

## 5. 已确定的界面（用户已在草图上确认）

草图文件在 `urlNavigation/.superpowers/brainstorm/.../content/overview-v2.html`，用户确认的是 v2 版本。

### 5.1 侧边栏

- 活动栏有一个独立的图标，点开是“网站导航”视图。
- 视图标题栏有两个按钮：**＋ 添加网站**、**⟳ 刷新**。
- 树结构分成两组：
  - **我的网站**：用户添加的网站。
  - **推荐**：插件内置的网站。
- 每个网站前面显示图标：优先显示网站的 favicon，拿不到时用 VS Code 内置的单色图标（Codicon）。**不用 emoji。**
- 已检测出不能嵌入的网站，在右侧用 ⚠ 标记（可以用 `description` 或者带颜色的 `ThemeIcon` 实现）。

### 5.2 打开网站

- 点击网站，会在编辑器区域打开一个标签页，**标题固定为 `README.md`**（用户的决定，和参考项目一样，让标签页看起来像在看文档）。
- 网站能嵌入：用一个铺满标签页的 iframe 加载这个网站。
- 网站不能嵌入：显示说明页（见 5.3），不加载 iframe。

### 5.3 说明页（不能嵌入时显示）

- 所有颜色都使用 VS Code 提供给 Webview 的主题 CSS 变量（`--vscode-foreground`、`--vscode-descriptionForeground`、`--vscode-textLink-foreground` 等），**不写死任何颜色**。深色、浅色、高对比度主题都要能自动适配。
- 内容偏左对齐，排版克制：一个淡化的小图标、一行标题“无法在编辑器中打开 xxx.com”、一句原因说明（“这个网站禁止被其他页面嵌入，这是它自己的安全设置，插件没有办法绕过。”）。
- 三个操作，样式是文字链接，不做成实心按钮：**在浏览器中打开**、**复制链接**、**从列表中移除**。“从列表中移除”只对“我的网站”里的网站显示。

## 6. 已确定的技术选择

这些是 Claude 提出、用户确认过的默认方案：

- **新建一个独立项目**：放在 `D:\prjx\` 下面，有自己独立的 git 仓库。参考项目 `urlNavigation` 不做任何修改。
- 用官方脚手架 `yo code`（`generator-code`，可以通过 npx 运行）生成项目：**TypeScript + esbuild + npm**。
- `engines.vscode` 使用脚手架生成的默认值（会比较新）。**不手写 `activationEvents`**，由 VS Code 根据贡献点自动推断。
- 网站列表**存放在 VS Code 的设置里**（`contributes.configuration` 定义一个数组配置项）。用户可以在插件界面里添加网站，也可以直接编辑 `settings.json`，开启设置同步后还能跨电脑同步。
- **检测能否嵌入**：由插件进程（Node 端）请求一次目标网址，跟随重定向，检查最终响应的：
  - `X-Frame-Options` 是 `DENY` 或 `SAMEORIGIN` → 判定为不能嵌入；
  - CSP 里的 `frame-ancestors` 不包含 `*`（`vscode-webview:` 来源一般不可能被网站列入白名单）→ 判定为不能嵌入；
  - 网络错误或超时 → **不判定为不能嵌入**，照常尝试用 iframe 加载。宁可漏判，也不能误判后把用户挡在外面。
- 写完代码后，Claude 写一份**中文讲解文档**，对照新项目的代码讲解各个部分是怎么工作的。讲到相关地方时，要指出参考项目里对应的问题，以及新代码是怎么避免的。
- **源码公开在 GitHub 上**（用户的决定）。计划里要包含“创建 GitHub 仓库并推送代码”这一步：这一步对外可见，执行前要征得用户同意。可以由用户自己在网页上创建仓库，也可以经用户同意后由 Claude 用 `gh` 创建。`package.json` 里的 `repository`、`bugs`、`homepage` 都填这个仓库的地址。仓库地址和 GitHub 用户名要等用户提供，不能自己猜一个填进去。在仓库创建之前，可以先不填这几个字段，开发阶段的打包警告可以接受；第 9 节第 4 条“打包没有警告”，等仓库地址和 publisher 都填好之后再验证。
- 发布：帮用户准备好发布所需的一切（README、CHANGELOG、图标、LICENSE、`.vscodeignore`、打包脚本）。注册 publisher、获取 token、执行 `vsce publish` 这些需要用户账号的步骤，由**用户自己操作**，Claude 写好操作步骤。

## 7. 由 Claude 决定的部分（用户没有明确表态，可以推翻）

- **项目名称**：暂定目录名和 `name` 为 `web-nav`，`displayName` 为“网站导航”。发布前用户可以改名。`publisher` 发布前必须由用户提供（这是用户自己的 publisher ID）。
- **添加网站的流程**：点击 ＋ → 输入框填网址（校验必须是 http/https 开头）→ 输入框填名称（默认填好域名，用户可以修改）→ 保存到设置 → 后台检测能否嵌入并刷新标记。
- **对“我的网站”的操作**（右键菜单）：在浏览器中打开、复制链接、重命名、修改网址、移除。
- **对“推荐”网站的操作**（右键菜单）：在浏览器中打开、添加到我的网站。另外提供一个设置项，可以隐藏整个“推荐”分组。
- **推荐分组内再按类别分子组**（比如“学习”“面试刷题”“博客”），因为推荐网站会比参考项目更多。
- **标签页**：始终只有一个标签页（和参考项目一样）。点击别的网站时，在同一个标签页里切换内容。原因是标题固定为 `README.md`，如果同时开好几个标签页，它们的名字都一样，用户分不清哪个是哪个。开启 `retainContextWhenHidden`，切到别的编辑器标签页再切回来时，网页不会重新加载。
- **检测结果缓存**在内存里（插件运行期间有效），点 ⟳ 刷新时重新检测。添加网站时检测一次，打开网站时如果还没有检测结果就先检测，再决定显示 iframe 还是说明页。
- **http:// 网站**：Webview 运行在安全上下文里，iframe 加载 `http://` 页面会被浏览器当作混合内容拦截，结果是一片空白，而且检测响应头也发现不了。处理方式：添加网站时，如果用户填的是 `http://`，先试一下同一个网址的 `https://` 能不能访问，能访问就自动改用 https；不能访问就照样保存，但打开时显示说明页，原因那一句换成“这个网站只支持不加密的 http 连接，VS Code 不允许在编辑器里加载这类页面。”，三个操作不变。推荐列表里只放 https 网站。
- **Webview 安全**：设置 CSP（`frame-src` 只允许 http/https，脚本只允许本插件自己的文件，使用 nonce），并限制 `localResourceRoots` 只能访问插件的 `media/` 目录。
- **测试**：判断能否嵌入的逻辑（解析响应头）写成纯函数，用单元测试覆盖。另外用脚手架自带的 `@vscode/test-cli` 写一个冒烟测试，确认插件能激活、命令都注册上了。
- **LICENSE 用 MIT**。README 里说明这个插件受“常用网站RSS”（zw990316/urlNavigation）的启发。

## 8. 交给实现者决定的部分

- 推荐网站的具体名单：参考项目里的网站可以作为候选（很多可能已经失效或改了域名，例如 leetcode-cn.com → leetcode.cn），再补充一些学习类网站。**每一个都要用第 6 节的检测逻辑实际验证能嵌入**，不能嵌入的不放进推荐列表。数量控制在 10–20 个。
- 设置项的具体键名和数据结构。
- 获取 favicon 的方式（直接用 `https://域名/favicon.ico` 也可以）。
- 代码目录怎么划分。原则是保持简单，每个文件只做一件事，方便讲解。
- 讲解文档的具体章节安排。
