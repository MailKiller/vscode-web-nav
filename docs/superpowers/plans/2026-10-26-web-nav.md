# 网站导航（web-nav）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新建一个 VS Code 插件：用户在侧边栏管理自己的网站和内置的推荐网站，在编辑器标签页里打开；不能嵌入的网站显示融入主题颜色的说明页。

**Architecture:** 纯逻辑（网址处理、响应头判定、HTML 生成、推荐数据）放在不依赖 `vscode` 的模块里，方便单元测试，也方便用 Node 脚本单独运行；`vscode` 相关的部分（树视图、Webview 面板、命令）是薄薄的一层，最后由 `extension.ts` 组装起来。网站列表存放在 VS Code 设置项 `webNav.sites` 中。

**Tech Stack:** TypeScript、esbuild、npm、`yo code`（generator-code）、`@vscode/test-cli` + mocha、`@vscode/vsce`。

**Spec:** `docs/superpowers/specs/2026-10-26-web-nav-design.md`（Task 1 会把它移到新仓库里）

## Global Constraints

- 项目目录 `D:\prjx\web-nav`，`name` 为 `web-nav`，`displayName` 为 `网站导航`。界面文字只用中文。
- 本机 VS Code 版本是 1.103.2：`engines.vscode` 不能高于 `^1.103.0`，`@types/vscode` 的版本不能高于 `engines.vscode`（否则 vsce 会报错）。
- `package.json` 里**不写** `activationEvents`。
- 设置项的命名空间是 `webNav`，所有命令 ID 都以 `webNav.` 开头。
- 运行时不引入任何 npm 依赖（`dependencies` 为空），也不做代理。
- Webview 的 CSS 和 HTML 里**不写任何颜色值**，颜色只用 `var(--vscode-*)`。
- 编辑器标签页：始终只有一个，标题固定为 `README.md`，开启 `retainContextWhenHidden: true`。
- Webview 必须设置 CSP，脚本使用 nonce；`localResourceRoots` 只允许 `media/` 目录。
- 说明页的文字必须一字不差：
  - 标题：`无法在编辑器中打开 ${hostname}`
  - 原因（blocked）：`这个网站禁止被其他页面嵌入，这是它自己的安全设置，插件没有办法绕过。`
  - 原因（insecure）：`这个网站只支持不加密的 http 连接，VS Code 不允许在编辑器里加载这类页面。`
  - 链接文字：`在浏览器中打开`、`复制链接`、`从列表中移除`（只对“我的网站”显示）
- 推荐列表里只放 https 网站，而且必须用检测脚本验证过 `ok`。
- 不修改 `D:\prjx\urlNavigation` 中已被 git 跟踪的文件。
- `publisher`、`repository`、`bugs`、`homepage` 等用户提供后再填，不要编造。
- 每条 commit message 末尾加：`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. 用户输入网址时不带协议（例如 `www.runoob.com`）：应该当作 `https://www.runoob.com/` 处理，不能直接报错。→ Task 2 `normalizeUrl` 测试
2. 重复添加同一个网站，包括只差一个结尾斜杠的情况（`https://a.com` 和 `https://a.com/`）：应该提示“已经在我的网站里了”，不能出现两条。→ Task 2 `findSite` 测试
3. 检测时网络出错或超时：判定为 `unknown`，照常用 iframe 打开，不显示 ⚠。→ Task 3 测试
4. 网址里带有 `"`、`<` 等特殊字符时，说明页和 iframe 页面要正确转义，不能把 HTML 注入到页面里。→ Task 5 测试
5. 用户手动编辑 `settings.json`，写进了格式不对的条目（缺少 url、类型不对、网址无效）：跳过这些条目，插件不能崩溃。→ Task 2 `sanitizeSites` 测试

### Task 3: 嵌入检测（`embedCheck.ts` + `embedChecker.ts`）

**Files:**
- Create: `src/embedCheck.ts`（**不 import vscode**）、`src/embedChecker.ts`、`src/test/embedCheck.test.ts`、`src/test/embedChecker.test.ts`

**Interfaces:**
- Produces:
  - `type EmbedVerdict = 'ok' | 'blocked' | 'insecure' | 'unknown'`
  - `type FetchLike = (url: string, init?: RequestInit) => Promise<{ url: string; headers: Headers; body: ReadableStream | null }>`
  - `verdictFromHeaders(headers: Headers): 'ok' | 'blocked'`
  - `checkEmbeddable(url: string, fetchFn?: FetchLike, timeoutMs?: number): Promise<EmbedVerdict>`：默认使用全局 `fetch`，超时 8000ms
  - `tryUpgradeToHttps(url: string, fetchFn?: FetchLike, timeoutMs?: number): Promise<string>`
  - `class EmbedChecker { constructor(fetchFn?: FetchLike); cached(url: string): EmbedVerdict | undefined; check(url: string): Promise<EmbedVerdict>; clear(): void; readonly onDidChange: vscode.Event<string>; dispose(): void }`

判定规则（来自 spec 第 6 节）：
- `X-Frame-Options` 按逗号拆分后，任意一项（不区分大小写）是 `deny` 或 `sameorigin` → blocked；`allow-from` 不算。
- CSP：用 `,` 拆成多条策略，每条用 `;` 拆成多个指令；只要有一条策略带 `frame-ancestors`，而且它的来源列表里没有 `*`，就判定为 blocked。
- `checkEmbeddable`：传入 `http:` 网址 → 直接返回 `insecure`，不发请求；发 GET 请求（`redirect: 'follow'`，`signal: AbortSignal.timeout(timeoutMs)`），如果最终的 `res.url`（空字符串时视为原网址）是 `http:` → `insecure`；否则用 `verdictFromHeaders` 判定；任何异常 → `unknown`。拿到响应头之后调用 `res.body?.cancel()`，不下载正文。
- `tryUpgradeToHttps`：已经是 https 的网址直接原样返回，不发请求；否则请求 https 版本，只要拿到响应（任何状态码都算）就返回 https 网址，出现异常就返回原网址。
- `EmbedChecker.check`：同一个 url 同时只发一个请求（并发调用共用同一个 Promise）；拿到结果后写入缓存，并触发 `onDidChange(url)`。

- [ ] **Step 1: 写失败测试** — 在 `embedCheck.test.ts` 里定义辅助函数 `fake(headers: Record<string,string>, finalUrl = '')`，返回一个 FetchLike。

```ts
test('CSP 无 frame-ancestors → ok', () => assert.strictEqual(h({ 'content-security-policy': "default-src 'self'" }), 'ok'));

test('请求异常 → unknown', async () => assert.strictEqual(await checkEmbeddable('https://a.com/', async () => { throw new Error('ENOTFOUND'); }), 'unknown'));
test('超时 → unknown', async () => assert.strictEqual(await checkEmbeddable('https://a.com/', (_u, init) => new Promise((_r, rej) => init!.signal!.addEventListener('abort', () => rej(new Error('abort')))), 20), 'unknown'));

test('升级失败返回原网址', async () => assert.strictEqual(await tryUpgradeToHttps('http://a.com/', async () => { throw 0; }), 'http://a.com/'));
```

### Task 5: Webview 面板（`html.ts` + `sitePanel.ts` + `media/panel.*`）

**Files:**
- Create: `src/html.ts`、`src/sitePanel.ts`、`media/panel.css`、`media/panel.js`、`src/test/html.test.ts`

**Interfaces:**
- Consumes：`Site`、`hostnameOf`（Task 2）、`EmbedVerdict`（Task 3）
- Produces:
  - `escapeHtml(s: string): string`
  - `buildIframeHtml(o: { url: string; cspSource: string }): string`：CSP 为 `default-src 'none'; frame-src https:; style-src ${cspSource} 'unsafe-inline';`，页面只包含一个铺满全屏、无边框的 iframe
  - `buildExplanationHtml(o: { url: string; reason: 'blocked' | 'insecure'; removable: boolean; cspSource: string; nonce: string; styleUri: string; scriptUri: string }): string`：CSP 为 `default-src 'none'; style-src ${cspSource}; script-src 'nonce-${nonce}';`，链接写成 `<a href="#" data-action="openExternal|copy|remove">`

  - `SitePanel.show(context: vscode.ExtensionContext, site: Site, source: PanelSource, verdict: EmbedVerdict): void`：单例模式，标题固定为 `README.md`；`ok`/`unknown` 时显示 iframe 页，`blocked`/`insecure` 时显示说明页；每次调用都重新设置 `webview.html`
